## 2. 如何预览

- **方式一（最简单，推荐）**：直接用浏览器打开 `prototype/ordering.html`（`file://` 双击即可，无需联网/构建）。
- **方式二（静态服务）**：在 `prototype/` 目录执行 `python3 -m http.server 8137`，浏览器访问 `http://<host>:8137/ordering.html`。

## 3. 参考代码结构（ordering.html 内分区）

| 区块 | 内容 | 后续开发可复用点 |
| --- | --- | --- |
| `<style> :root` | 设计色板 CSS 变量（对齐 tailwind 自定义色） | 直接映射为设计 token |
| HTML 结构 | 顶部栏 / 菜单区 / 购物车侧栏 / 移动底部条 / 弹层 / Toast | 信息架构与组件划分 |
| `CATEGORIES` / `DISHES` | 分类与 10 个 Mock 菜品（含 options） | 替换为接口字段即可对接真实菜单 |
| `state` + `render*` | 内存状态与渲染：分类、列表、购物车、底部条 | 状态模型可迁移到 reducer/store |
| 计价函数 | `cartSubtotal / discount / payable`、半份 0.58 | R1/R3/R4 计价规则的直接参照 |
| `addToCart/changeQty` | 合并键 = 菜品+规格、数量边界 | 购物车合并与边界逻辑 |
| `openSpec/openCheckout/submitOrder` | 规格弹窗、结算、下单成功闭环 | 结算/下单交互基线 |
| 响应式 CSS | 560 / 980 断点、底部抽屉、安全区 | 移动适配实现参照 |

## 4. 与现网 React 应用的关系

- 数据字段（菜品/分类/规格/价格/半份系数/满减）与文案对齐 `src/data/menu.ts`、`src/i18n.ts`，保证体验连续。
- 本原型**有意省略**履约进度、退菜、呼叫服务、多语言、老人模式、桌台绑定等，以贴合本次需求范围；这些能力现网 React 应用已具备。

## 6. 已知限制（原型范围）

- 菜品图为 emoji 占位（零依赖考虑），正式开发替换为真实图片/CDN。
- 订单号为本地时间生成、支付为模拟，不代表真实交易。
- 超级辣风险确认使用原生 `confirm`，正式开发建议替换为与现网一致的自定义 Dialog。
