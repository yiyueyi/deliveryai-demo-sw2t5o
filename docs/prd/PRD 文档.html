1. 背景与目标

仓库已有完整的 React+Vite 火锅点餐应用，但需构建后运行，不便“双击即开”快速预览。本需求交付一个单文件、零构建、零外部依赖的点餐页面，覆盖“浏览 → 加购 → 数量/合计 → 结算 → 下单成功”闭环，视觉对齐现网设计系统。

非目标

  • 不替代现有 React 应用，不接入真实后端 / 支付 / 库存 / 登录。
  • 不做履约进度、退菜、呼叫服务、多语言、老人模式等增强能力。

2. 信息架构

顶部栏（品牌 · 营业状态 · 桌台）
└── 主体：≥980px 菜单+购物车双栏 ｜ <980px 单列
    ├── 菜单区：Hero / 搜索 / 分类胶囊 / 菜品卡片网格
    └── 购物车侧栏（仅桌面）
移动端：底部常驻结算条（购物车入口 + 合计 + 去结算）
弹层：规格选择 ｜ 购物车抽屉(移动) ｜ 结算 ｜ 下单成功  ＋ 全局 Toast

3. 功能性需求

编号需求要点
F1 P0菜品分类与列表6 分类（推荐为全部）、即时筛选高亮；卡片含图/标签/名/描述/起售价/加购；10 个示例 SKU。
F2 P1搜索按名称/描述实时包含匹配，可与分类叠加；无结果有空状态。
F3 P0规格选择与加购份量/口味/辣度动态展示；半份按 0.58 实时计价；超级辣二次确认；按“菜品+规格”合并入车并 Toast。
F4 P0购物车明细/规格/行金额、数量步进（减到 0 移除）、总份数/小计/合计；空车空状态；桌面侧栏、移动抽屉。
F5 P0结算逐行明细、小计、满减（满 100 减 30）、应付；移动支付/POS 二选一；空车禁入。
F6 P0下单成功反馈成功图标、订单号、份数、支付方式、实付金额；成功后清空购物车。
F7 P1全局交互遮罩/✕/Esc 关闭、Toast 反馈、弹层锁定背景滚动。

4. 非功能性需求

类别要求
N1 可移植性 P0单个自包含 HTML，不引用任何外链 CSS/JS/字体/图片；emoji + 内联 SVG；支持 file:// 双击与静态服务。
N2 兼容性 P0主流 evergreen 浏览器；广泛支持的 JS/CSS，不依赖框架。
N3 响应式 P0560 / 980 断点：单列→双列→双栏；移动端底部条+底部抽屉；适配安全区；分类条横滚。
N4 可访问性 P1触控目标≥38px、aria-label/role=dialog、可读对比度。
N5 性能 P1约 36KB 单文件，首屏即时；内存过滤无网络往返。
N6 可维护性 P1数据与渲染分离（CATEGORIES/DISHES），色值集中于 CSS 变量。
N7 安全 P2动态文本统一转义防注入；不使用 localStorage 与隐私数据。

5. 业务规则

编号规则
R1半份价 = round(原价 × 0.58)（沿用现网，待业务最终确认）
R2购物车合并键 = 菜品 ID + 规格串；不同规格独立成行
R3合计 = Σ 单价 × 数量（优惠前口径）
R4满 ¥100 减 ¥30，应付 = 小计 − 优惠
R5“超级辣”需二次风险确认
R6下单生成原型订单号 FD+年月日时分秒，并清空购物车
R7空车不可结算；搜索无结果有空状态

6. 验收标准

#验收点预期实测
AC1查看菜品及价格分类 + 10 菜品含价格✅ 通过
AC2选菜并调数量规格加购、增减/移除、半份计价✅ ¥42→¥24，×2=¥48
AC3购物车明细与总价数量/小计/合计联动✅ ¥24×2+¥68=¥116
AC4结算/下单反馈满减、应付、成功页并清空✅ −¥30，实付¥86
AC5桌面/移动适配双栏/单列、底部条+抽屉✅ 1280 / 390 视口
AC6零依赖直接打开file:// 可用、无外链✅ 单文件内联
AC7搜索与分类过滤/筛选/空状态✅ 实测正确
