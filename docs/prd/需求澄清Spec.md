# 点餐系统 HTML 页面 · 需求澄清 Spec

> 节点：需求设计 ｜ 形态：独立单文件原型（标准版）
> 说明：本文件只承载需求决策（目标 / 范围 / 业务规则 / 边界 / 场景概要 / 未决项），详细交互与验收见《PRD 文档》。

## 1. 需求与目标

- **一句话需求**：提供一个可直接在浏览器打开的点餐系统 HTML 页面，覆盖“浏览菜品 → 加入购物车 → 调整数量 → 查看合计 → 结算/下单”的核心点餐体验。
- **背景**：当前仓库已存在基于 React + Vite 的完整火锅点餐应用（`hdl-order-demo`，能力已覆盖本次诉求），但需要 `npm` 构建、无法双击直接打开。需求方希望得到零依赖、可直接预览、易维护的页面。
- **目标**：
  1. 用原生 HTML/CSS/JS 交付一个**单文件、零构建、零外部依赖**的点餐页面，双击 `prototype/ordering.html` 即可运行。
  2. 在视觉上对齐仓库既有设计系统（rice / chili / charcoal / amber 色板），保持产品体验一致。
- **成功标准（意图）**：
  - 首次使用者无需说明即可完成“选菜 → 加购 → 结算 → 看到下单成功反馈”的完整闭环。
  - 桌面与手机宽度下均可正常浏览与操作。

## 2. 范围与业务规则

### 2.1 本期做（In Scope）

- 菜品分类切换（推荐 / 锅底 / 牛羊肉 / 海鲜河鲜 / 蔬菜豆品 / 主食饮品）与关键字搜索。
- 菜品列表展示：图片、名称、描述、价格、营销标签。
- 菜品规格选择：份量（半份 / 整份）、口味、辣度；半份按 **0.58** 系数计价（沿用现网规则，`推断`）。
- 加入购物车：同菜品同规格自动合并数量。
- 购物车：展示已选商品、规格、单价、数量加减、单项金额与菜品合计；数量减到 0 自动移除。
- 结算：账单明细、菜品小计、满减优惠、应付合计、支付方式选择。
- 下单/支付成功反馈：订单号、份数、支付方式、实付金额，并清空购物车。
- 桌面端右侧常驻购物车栏；移动端底部常驻结算条 + 购物车抽屉。

### 2.2 本期不做（Out of Scope）

- 不接入任何后端 API、登录、真实支付、库存与桌台绑定（数据全部为前端 Mock / 内存态）。
- 不做履约进度（后厨接单/制作/上菜）、退菜、呼叫服务、多人协同、多语言、老人模式等现网增强能力。
- 不替换、不改造现有 React 点餐应用；新页面以独立文件并存。

### 2.3 核心业务规则与边界

| 编号 | 规则 | 来源 |
| --- | --- | --- |
| R1 | 菜品价格为整数元，半份价 = `round(原价 × 0.58)`。 | 沿用 React 版 `MenuView`（`推断`，已与现网一致） |
| R2 | 购物车合并键 = 菜品 + 完整规格串；不同规格分别成行。 | 产品规则 |
| R3 | 购物车合计 = Σ(单价 × 数量)，不区分优惠。 | 产品规则 |
| R4 | 满减：菜品小计 ≥ 100 元减 30 元；应付 = 小计 − 优惠。 | 沿用 React 版 `CheckoutView`（`推断`） |
| R5 | 选择“超级辣”需二次风险确认，取消则不采用该辣度。 | 沿用 React 版超级辣风险提示（`推断`） |
| R6 | 下单成功后清空当前购物车，订单号按本地时间生成（原型规则，非真实单号）。 | 原型规则 |
| R7 | 空购物车禁止进入结算；无搜索结果给出空状态提示。 | 边界处理 |

## 3. 用户与场景（概要）

- **目标用户**：到店顾客（自助扫码点餐）与需要快速预览点餐体验的产品/研发评审者。
- **核心场景**：
  1. 顾客按分类或搜索浏览菜品，查看价格与描述。
  2. 选择规格与份量后加入购物车，随时调整数量。
  3. 在购物车/底部条查看份数与合计，进入结算核对账单、选择支付方式。
  4. 确认支付后看到明确的下单成功反馈。

## 4. 未决项

- 暂无阻塞性业务未决项。以下为后续真实开发需产品/业务再确认（不阻塞本原型）：
  - `待确认`：满减门槛（满 100 减 30）、半份 0.58 系数、超级辣风险文案是否为正式业务规则。
  - `技术待设计`：菜品/分类/价格数据未来由哪个接口提供、订单号与优惠由前端还是后端计算。
  - `交付上下文`：原型文件 `prototype/ordering.html` 与现网 React 应用并存，后续是否合并入正式前端由研发评估。
